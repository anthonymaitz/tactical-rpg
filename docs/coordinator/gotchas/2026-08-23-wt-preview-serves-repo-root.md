# tactical-rpg worktree toolchain

- **A `wt` preview for tactical-rpg returns HTTP 403 "Blocked request … host not allowed", and the fix is NOT to touch `allowedHosts`.** The task container's command is `npm install && npx vite` run from `/app` — the repo root. There is no Vite config at the repo root; the game lives in `apps/game`, and `apps/game/vite.config.ts` already sets `server: { host: true, allowedHosts: true }`. Vite therefore starts, serves the wrong directory, and rejects the preview hostname because it never loaded that config. The dev-server log looks perfectly healthy (`VITE ready in 76 ms`), so nothing signals the problem until you actually fetch the URL — and the headless capture just returns a screenshot of Vite's block page. Root cause is that `package.json` has no root `dev` script for a generic runner to find (only `pnpm --filter game dev`). Until a root `dev` script exists, treat the preview as unavailable for this repo and verify client changes by building (`VITE_API_URL=… VITE_SERVER_URL=… pnpm --filter game build` — the `requireEnv` plugin hard-fails a production build without both vars) and inspecting `apps/game/dist`.

- **`pnpm` is not on PATH on this host, despite `packageManager: pnpm@11.15.0`.** There is no `corepack` either. Use `npx --yes pnpm@11.15.0 <cmd>`; it honours the committed lockfile and leaves it untouched. Do not fall back to `npm install` at the repo root — that is what the task container does, and it drops an untracked `package-lock.json` into the tree that `.gitignore` does not cover, so it shows up in `git status` looking like your change.

- **The `../simplequest` and `../playsets experiments/apps/client` entries in `pnpm-workspace.yaml` are vestigial — do not spend time making them resolve in a worktree.** `pnpm install` reports `Scope: all 8 workspace projects` (the in-repo packages only), those two contribute nothing, and pnpm does not warn. No `package.json` declares `playsets-board` or `simple-quest` as a dependency, the committed lockfile has no importer for either, and `require.resolve` fails for both in the **main checkout** too. The worktree reproduces main exactly (typecheck 0; 160 tests, 3 failing).
